# AM24 — преобразователь 4–20 мА → частота / импульсы

Прототип на NUCLEO-G474RE с изолированным входом на AD7124-4. ТЗ, расчёт погрешностей, описание схемы, перечень элементов с ценами и методика калибровки — в [docs/AM24_spec.pdf](docs/AM24_spec.pdf).

```
docs/       ТЗ и описание схемы (PDF)
firmware/   прошивка STM32G474 (CMake, без HAL, регистры CMSIS)
hardware/   схема платы-шилда KiCad 10, PDF, перечень элементов, нетлисты
tools/      утилита на ПК (am24.py) и генераторы схемы KiCad (Python)
```

Заголовки CMSIS подключены как подмодули git, поэтому клонируйте с ними:

```bash
git clone --recursive https://github.com/ocidburn/4-20-ma-to-pulse-output.git
```

Если репозиторий уже склонирован без них: `git submodule update --init`. На Windows перед этим может понадобиться `git config --global core.longpaths true`.

## Прошивка

### Сборка

Нужны CMake (есть в `C:\Program Files (x86)\CMake`) и компилятор из STM32CubeIDE 2.1.1 — его путь находится автоматически, другой можно указать через `-DARM_TOOLCHAIN_DIR=<папка bin>`. Ninja тоже берётся из CubeIDE.

```bash
cd firmware
cmake -S . -B build -G Ninja
cmake --build build
```

Результат: `build/am24.elf`, `am24.hex`, `am24.bin` (≈ 35 КБ flash, 10 КБ RAM).
Без TCXO (на внутреннем генераторе, только для отладки): `cmake -S . -B build -G Ninja -DUSE_HSI=ON`.

### Прошивка платы

Проще всего скопировать `build/am24.bin` на диск NOD_G474RE, который Nucleo создаёт при подключении по USB. Либо открыть `am24.elf` в STM32CubeProgrammer.

### Выводы (Arduino-разъём Nucleo)

| Вывод | Arduino | Назначение |
|---|---|---|
| PA5 / PA6 / PA7 | D13 / D12 / D11 | SPI1 SCK / MISO / MOSI → ISO7741 → AD7124 |
| PB6 | D10 | CS AD7124 |
| PA0 | A0 | частотный выход (TIM5_CH1) |
| PA1 | A1 | импульсный выход |
| PA4 | A2 | светодиод «Авария» |
| PA2 / PA3 | — | LPUART1 → виртуальный COM-порт ST-LINK, 115200 8N1 |
| PF0 | — | вход 10 МГц от TCXO (HSE bypass) |
| PB10 | D6 | PPS от модуля GPS (TIM2_CH3), разъём J7 на шилде |

**Перед запуском с TCXO** проверьте по руководству Nucleo-G474RE (UM2505), какие перемычки (solder bridges) перепаять, чтобы подать внешний такт на OSC_IN. Если HSE не запустится, прошивка сама перейдёт на внутренний генератор и сообщит об этом при старте («HSI (inaccurate!)»).

### Как работает

- АЦП: секвенсор перебирает три канала, ≈ 150 мс на круг. Каналы 0 и 1 — шунт в прямом (AIN0−AIN1) и обратном (AIN1−AIN0) порядке: полуразность пары убирает смещение АЦП и его дрейф. Канал 2 — AIN6, делитель термистора NTC от опоры. Биполярный режим, усиление 1, буферы включены (у канала NTC без буфера AIN−), опора REFIN1 = 3,0 В, пост-фильтр 20 отсч./с (подавление 50/60 Гц).
- Температурная поправка: ток × (1 − `tc_ppm`·10⁻⁶·(T − T₀)), где T — температура по NTC, T₀ — запоминается командой `CAL CLEAR`. Затем калибровка — кусочно-линейная, до 11 точек.
- Частота: 32-битный TIM5 на 170 МГц, период в формате 32.32 с дробным накоплением — средняя частота точна до долей ppm, отдельный период отличается не больше чем на 1 такт (5,9 нс).
- Импульсы: каждые 1 мс расход интегрируется от того же генератора; целые импульсы копятся в счётчике и выдаются с заданной длительностью (пауза = длительности). Поправка генератора действует и на импульсы.
- GPS: TIM2 захватывает фронты PPS; ошибка TCXO считается за окно `gps_win` секунд (по умолчанию 100, разрешение ≈ 0,001 ppm) и сразу применяется. Без PPS работает последняя измеренная поправка, после перезапуска — `tcxo_ppm`. На каждом фронте PPS запоминается точная сумма импульсов с дробной частью — по ней утилита проверяет импульсный выход.
- Аварии: ток < `alarm_lo` или > `alarm_hi` (NE43), ошибка АЦП или нет данных 500 мс, переполнение буфера импульсов. Бит 0x10 — термистор не отвечает или температура ушла от калибровочной больше чем на `t_window`: только светодиод, выходы работают.
- Настройки и калибровка хранятся в последней странице flash. **Во время SAVE выходы замирают примерно на 25 мс.**

### Команды (терминал 115200 8N1, каждая строка заканчивается `OK` или `ERR ...`)

| Команда | Что делает |
|---|---|
| `*IDN?` | идентификация |
| `MEAS?` | ток, частота, расход, сумматор, температура, поправка генератора, аварии |
| `RAW?` | ток до калибровки (с поправкой и без), его среднее за 3 с, температура |
| `WIN START` / `WIN?` | окно усреднения: среднее всех пар с момента `WIN START` |
| `CONF?` | все настройки |
| `SET <ключ> <значение>` | изменить настройку (действует сразу, `SAVE` — сохранить) |
| `CAL?` / `CAL CLEAR` / `CAL ADD <мА>` | точки калибровки (до 11); `CAL ADD` берёт среднее окна, если оно открыто |
| `SAVE` / `DEFAULTS` | сохранить / заводские настройки |
| `TOTAL?` / `TOTAL RESET` | сумматор импульсов (`EXACT` — с дробной частью) |
| `GPS?` / `GPS STORE` | состояние PPS и измеренная ошибка генератора / записать её в `tcxo_ppm` (затем `SAVE`) |
| `FTEST <Гц>` / `FTEST OFF` | принудительная частота для калибровки генератора |

Ключи настроек: `fmin`, `fmax` (Гц), `cutoff` (% диапазона), `damp` (с), `qmax` (ед./ч при 20 мА), `pval` (ед./имп), `pwidth` (мс), `ppol` (1 — активный высокий уровень на PA1), `alarm_mode` (0 — 0 Гц, 1 — `alarm_freq`, 2 — удержание), `alarm_freq`, `alarm_lo`, `alarm_hi` (мА), `tcxo_ppm`, `gps` (1 — поправка по GPS), `gps_win` (с), `vref`, `rshunt`, `tc_ppm` (ppm/°C), `t_window` (°C), `ntc_r25`, `ntc_beta`, `ntc_rfix`.

Настройки версии 0.2 несовместимы с 0.1: после прошивки действуют заводские, калибровку нужно выполнить заново.

## Утилита на ПК

```bash
pip install pyserial pyvisa pyvisa-py
python tools/am24.py ports                      # список COM-портов
python tools/am24.py -p COM5 meas --watch       # показания
python tools/am24.py -p COM5 set qmax 50 --save
python tools/am24.py -p COM5 gps                # PPS и ошибка генератора; --store — сохранить её
python tools/am24.py -p COM5 --rref 100.000123 --dmm GPIB0::22::INSTR --dmm-type hp3458 tempco --apply
python tools/am24.py -p COM5 --rref 100.000123 --dmm GPIB0::22::INSTR --dmm-type hp3458 cal
python tools/am24.py -p COM5 --rref 100.000123 --dmm GPIB0::22::INSTR --dmm-type hp3458 verify
python tools/am24.py -p COM5 --rref 100.000123 --dmm GPIB0::22::INSTR --dmm-type hp3458 pulses --seconds 1000
python tools/am24.py -p COM5 log --interval 1   # журнал в CSV
python tools/am24.py --sim cal                  # пробный прогон без железа
```

- `--rref` — сопротивление эталонного резистора из сертификата; `--rref-tc` и `--rref-temp` пересчитывают его на текущую температуру.
- `--dmm` — адрес мультиметра в VISA (GPIB, USB, LAN или COM). `--dmm-type scpi` (по умолчанию) — Keysight, Fluke, Keithley; `hp3458` — язык 3458A. `--dmm-init` задаёт свои команды настройки. Без `--dmm` среднее за окно вводится вручную (запустите статистику на мультиметре, когда утилита попросит).
- `cal` — 9 точек от 4 до 20 мА, выдержка 20 с, окно 60 с (`--points`, `--settle`, `--window`). Утилита усредняет преобразователь (`WIN`) и мультиметр за одно и то же окно и показывает отклонение точек от гладкой кривой — так видна плохая точка.
- `verify` — 10 точек между точками калибровки, допуск `--limit-ppm` (по умолчанию 10 ppm диапазона = 0,001 %), отчёт CSV.
- `tempco` — температурный коэффициент `tc_ppm`: окна по 60 с в течение `--minutes` (по умолчанию 120) при 20 мА, пока температура под крышкой меняется хотя бы на 0,5 °C. Выполнять до калибровки.
- `pulses` — проверка импульсного выхода по времени GPS: дробная сумма импульсов на фронтах PPS против тока эталона за то же число секунд.
- В неопределённость результата `verify` и `pulses` не входит погрешность самого эталона — её считают отдельно (см. документ, раздел «Калибровка и проверка»).

## Плата-шилд (KiCad)

`hardware/am24_shield.kicad_sch` — полная схема на листе A2 (93 элемента), формируется скриптом:

```bash
python tools/gen_wired.py
```

Элементы нарисованы стандартными символами KiCad и соединены проводниками. Шины питания (+24V, +5V, +3V3, +5V_ISO, +3V3_ISO, GND, AGND) показаны символами питания, метки остались только у сигналов FOUT, POUT, ALARM между выходными каскадами и разъёмом Nucleo и у NTC (делитель термистора к AIN6). ERC KiCad 10: 0 ошибок. Рядом лежат `am24_shield.pdf`, нетлист и `am24_shield_bom.csv` — перечень элементов.

Клеммы выходов X3/X4: **1 — OC, 2 — PP (24 В), 3 — 0 В**.

Для режима 0,001 % добавлены термистор RK1 с делителем R9, C33 (ставится вплотную к DA1 и R2, всё под одной крышкой) и разъём J7 для модуля GPS: 1 +5V, 2 +3V3, 3 GND, 4 PPS → R10 → D6.

Старый вариант схемы на метках (`tools/gen_schematic.py`) перезаписывает тот же файл — не запускайте его. Совпадение соединений двух вариантов проверяется так (`am24_shield_labels.net` — нетлист старого варианта):

```bash
cd hardware
python ../tools/cmp_net.py am24_shield_labels.net am24_shield.net
```

- Цоколёвки AD7124-4, ISO7741, LTC6655, ADP7118, NXE1, ASTX-H11 и R-78HB сверены с документацией производителей.
- Стандартные цоколёвки DN2540N5 (G-D-S), NTD3055L104 (G-D-S), BCP56/BCP53 (B-C-E) и BAV199 (1 — анод D1, 2 — катод D2, 3 — общий) из текста документации не подтверждены — сверить с чертежами.
- Посадочные места F1 и F2 (Bourns MF-R, шаг 5,1 мм) в библиотеке KiCad нет — назначить вручную. У ADP7118 сверить размер теплового пятна с документацией.
- Добавлены 10 кОм на выводы МК (выходные каскады выключены при сбросе) и балласт R6 270 Ом для NXE1 (модулю нужно не меньше 10 % нагрузки).
- Предупреждения ERC о библиотеках исчезнут после первого запуска KiCad (он создаст таблицы библиотек).

## Что не проверено

- Прошивка собрана, но на реальной плате не запускалась: нет железа. Обработка пар, температурная поправка, окна и GPS проверены только на симуляторе утилиты (`--sim`), он повторяет протокол, но не код прошивки.
- Команды мультиметров в `am24.py` (SCPI и язык 3458A) на приборах не проверялись.
- Адреса регистров AD7124, битовые поля и коды (пост-фильтр 20 отсч./с = FILTER 7 / POST_FILTER 5, режим full power = 2, ID 0x04/0x06/0x07) сверены с официальным драйвером ADI [no-OS ad7124.h / ad7124.c](https://github.com/analogdevicesinc/no-OS/tree/main/drivers/adc/ad7124). Электрические пределы (диапазон входов с буферами AVSS + 0,1 … AVDD − 0,1 В, опора 3,0 В при AVDD 3,3 В) сверены с документацией AD7124-4, ред. E.
- CRC на SPI АЦП не включён; связь контролируется флагом ошибки и тайм-аутом данных.
- Время установления АЦП при переключении трёх каналов взято равным периоду пост-фильтра (50 мс); на плате проверить по флагам и частоте пар.
